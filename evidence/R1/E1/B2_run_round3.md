## 新的性能瓶颈（第三层，已定位）

加上解析缓存后，运行**已通过 features_once 与 CV 段**（每谱特征 0.18–3.04s，36 谱），
但**卡在最后的逐曲配对 bootstrap 10,000 次**：

- 我在每次重采样里**重新调用 `f1_of`**，而它内部要跑 `scipy.linear_sum_assignment`；
- 对照基线 `bp2/bp4` 的预测集每 run 上万条 ⇒ 单次匹配 O(10⁴) 量级 ⇒ 10⁴ 次重采样 = **10⁸+** 且常数极大。

## 修法（下一轮，仍在 B2 脚本内）

**对已算好的逐 run 计数做 bootstrap**：重采样「曲目组 → 其 runs 的 (tp,fp,fn)」并求和，再算 P/R/F1。
数学上与"重跑匹配"的配对 bootstrap 等价（同一批逐 run 计数），但把 10⁴ 次重活换成 10⁴ 次纯加法 ≈ 10⁶ 量级。
`B2_perf.csv` 里已存逐 run 的 tp/fp/fn，可直接作为 bootstrap 的输入。
