# B2 首次运行：**性能阻塞**（未出数）

## 事实

`tools/b2_harmony_segments.py` 首次运行（271 runs × K∈{1,2,3}）**超过 10 分钟未完成**，被终止；**未写出任何产物**（脚本在末尾才写文件）。

## 根因（实现问题，不是规格问题）

- B2 需要**每个锚点**的 `bass_pc` / `pcs`；而 `anchor_features(notes, t)` 每次调用都要**全表扫描**音符
  ⇒ 复杂度 `O(n_anchors × n_notes)`。
- 量级：271 runs × 每 run ~2,300 锚点 × 每谱 2,000–5,800 音符 ≈ **十亿级** Python 级操作。
- 且我对 **3 个 K 各重建一次**特征，白白多花 3×。

## 修法（下一轮，仍只动新文件）

1. **每 run 只算一次特征**：先 build 出 `feats`（一次），再对 K∈{1,2,3} 复用同一 `feats` 做边界/段/预测。
2. 仍调用 `score_features.anchor_features`（规格要求"不重写"），但**先用锚点索引把候选音符桶化**
   再传入（同一 `t` 下选择结果不变），把单次调用从 O(全谱) 降到 O(桶内)。
3. 预期：从"十亿级"降到"百万级"，单轮可完成。
